Hierarchical Disaggregation for Large-Scale MoE Model Serving

Background

Two orthogonal disaggregation techniques have been proposed for efficient LLM serving:

Prefill-Decode (P-D) Disaggregation

  • Problem: Prefill (compute-bound) and decode (memory-bound) phases have different resource characteristics. Colocating them causes interference and suboptimal batching.
  • Solution: Separates prefill and decode into distinct nodes. KV cache is transferred from prefill to decode nodes.
  • Benefit: Enables independent scaling and reduces phase interference.
  • Limitation: Focuses only on phase-level separation. Does not address low GPU utilization in MoE experts within the decode phase (i.e., MoE sparsity), as attention and experts remain colocated.

Attention-Expert Disaggregation

  • Problem: MoE sparsity reduces tokens per expert (batch × top_k / num_total_experts), making FFN memory-bound and causing low GPU utilization.
  • Solution: Separates attention and MoE FFN modules onto different GPU pools and replicates attention nodes to aggregate tokens from multiple sources.
  • Benefit: Increases effective batch size per expert, restoring compute-intensity.
  • Limitation: Does not address P-D interference. Limited to homogeneous hardware.

Both approaches are validated in production systems (SGLang, ByteDance) but have been studied in isolation.

Limitation

Applying either technique alone leaves efficiency gaps:

  • P-D Disaggregation only: Addresses P-D phase interference, but leaves MoE underutilization in the decode phase unresolved.
  • Attention-Expert Disaggregation only: Addresses MoE sparsity and enables heterogeneous hardware deployment, but still suffers from P-D interference.

Naively combining them introduces new challenges:

  • Increased network communication overhead: P→D transfer and Attention↔Expert communication
  • Need unified scheduling across main operations: chunked prefill, KV cache transfer (from P to D), attention-expert ping-pong pipeline overlapping across microbatches

Proposed Idea

Hierarchical Architecture: Apply P-D disaggregation at the top level, then Attention-Expert disaggregation within the decode cluster.

  • Prefill cluster: Compute-bound already to handle the entire prompt. Attn-Expert disaggregation can be applied on-demand (e.g., chunked prefill).
  • Decode-Attention nodes: Perform attention using KV cache received from prefill nodes. GPUs with high memory bandwidth are better suited.
  • Decode-Expert nodes: Execute MoE FFN via ping-pong pipeline with Attention nodes. GPUs with high computation efficiency are better suited.

Communication Co-scheduling: Overlap KV transfer (Prefill→Decode-Attention) with Decode-Expert computation phase to avoid network contention with Attn-Expert communication.
